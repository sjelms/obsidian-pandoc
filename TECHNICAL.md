# **TECHNICAL DOCUMENTATION: Pandoc Plugin Fork **

## **📌 Project Overview**

**Project Name**: Obsidian Pandoc Plugin (Aliased Citations Fork)

**Description**: This is a forked version of the [Obsidian Pandoc Plugin](https://github.com/OliverBalfour/obsidian-pandoc). The primary goal of this fork is to modify the plugin's behavior to correctly render aliased Pandoc-style citation links. The plugin will be updated to display only the alias text for links formatted as `[[@citationKey|Alias Text]]`, reverting to Obsidian's default rendering behavior for these specific cases, while preserving the standard citation rendering for non-aliased links like `[[@citationKey]]`.  

**Primary Language(s)**: TypeScript  

**Environment**: Obsidian Desktop App (macOS / Linux / Windows)  

**Dependencies**: Node.js, npm, Obsidian API, esbuild. All required packages are listed in package.json.

## **🗂️ Directory Structure**

The project follows the standard structure for an Obsidian community plugin.

/obsidian-pandoc  
│  
├── main.ts             # Plugin entry point, registers commands and settings.  
├── renderer.ts         # Handles Markdown-to-HTML conversion and post-processing. **(This is where our changes will be made)**  
├── pandoc.ts           # Manages the execution of the Pandoc command-line tool.  
├── settings.ts         # Creates the settings UI for the plugin.  
├── global.ts           # Contains shared interfaces and helper functions.  
├── styles/             # Contains CSS styles injected into HTML exports.  
├── main.js             # The compiled JavaScript output that Obsidian runs. (Generated by `npm run dev`)  
├── manifest.json       # Plugin metadata for Obsidian.  
├── package.json        # Project dependencies and scripts.  
├── tsconfig.json       # TypeScript compiler configuration.  
├── esbuild.config.mjs  # Build script configuration.  
└── README.md           # Original project README.

**`main.ts`**: Initializes the plugin, adds the export commands to the command palette, and creates the settings tab.  

**`renderer.ts`**: The core logic for pre-processing Markdown. It uses Obsidian's renderer to create HTML and then cleans/modifies that HTML before it's sent to Pandoc. **The logic for handling aliased citations will be added here.**  

**`pandoc.ts`**: A wrapper for spawning the Pandoc executable with the correct arguments for file conversion.  
**settings.ts**: Defines the user-facing settings panel within Obsidian.  

**`main.js`**: This is the bundled, production-ready file that Obsidian actually loads. It is generated from the TypeScript source files during the build process (npm run dev or npm run build). You should not edit this file directly.

## **⚙️ Setup Instructions**

These instructions are for setting up a local development environment to modify and build the plugin.

### **1. Fork & Clone the Repository**

Fork the original repository and clone your version into your Obsidian vault's plugin directory.

# Navigate to your vault's plugin folder  
`cd /path/to/your/vault/.obsidian/plugins/`

# Clone your forked repository  
```bash
git clone https://github.com/sjelms/obsidian-pandoc.git  
cd obsidian-pandoc
```

### **2. Install Dependencies**

Install the required Node.js packages using npm.
```bash
npm install
```

### **3. Build the Plugin**

Run the development script. This will compile the TypeScript source into main.js and will automatically re-compile whenever you save a change to a source file.
```bash
npm run dev
```
Keep this script running in a terminal window while you are making edits.

### **4. Enable in Obsidian**

* Open Obsidian.  
* Go to ``Settings > Community plugins``.  
* Disable the official "Pandoc Plugin" if you have it installed.  
* Enable your forked version of the plugin (it will have the same name).  
* To see changes after saving a file, you may need to reload Obsidian (you can find "Reload app without saving" in the Command Palette).

## **🧱 Project Architecture**

### **🌀 Workflow Overview**

The plugin's export process, including our modification, follows these steps:

1. **User Action**: The user opens a Markdown file in Obsidian and triggers an export command from the Command Palette (e.g., "Pandoc: Export as Word Document").  
2. **HTML Rendering**: The plugin takes the content of the active file and uses Obsidian's built-in MarkdownRenderer to convert it into an HTML fragment. This ensures that Obsidian-specific syntax (like embeds and aliased links) is processed correctly.  
3. **HTML Post-Processing**: The generated HTML is passed to the postProcessRenderedHTML function in renderer.ts.  
   * The function iterates through all link (`<a>`) elements in the HTML.  
   **Custom Logic (Our Change)**: It specifically identifies aliased citation links (`[[@citekey|alias]]`). When found, it replaces the entire link element with its plain text alias.  
   * Other links and images are processed to have correct, filesystem-relative paths.  
4. **Pandoc Execution**: The cleaned HTML (or the original Markdown, depending on settings) is passed to the Pandoc command-line tool via pandoc.ts.  
5. **File Output**: Pandoc converts the input into the desired final format (e.g., .docx, .pdf) and saves it to the specified output directory.

## **🧼 Post-Processing Rules**

This section details the specific modification to achieve the desired aliased citation behavior.

### **✨ Target: Aliased Citation Link Cleanup**

**Goal**: To prevent aliased citation links from being processed incorrectly by Pandoc's citation engine, which results in output like (Felstead and Unwin 2016|Learning Outside The Formal System).  
**Desired Behavior**:  
  * `[[@Felstead2016-ut]]` should render as `(Felstead and Unwin 2016)`. (No change to existing behavior).  
  * `[[@Felstead2016-ut|Learning Outside The Formal System]]` should render as `Learning Outside The Formal System`. (This is the change).

### **🔎 Implementation Details**

The change is implemented within the `postProcessRenderedHTML` function in `renderer.ts`.

1. **File to Modify**: `renderer.ts`  
2. **Function to Modify**: `postProcessRenderedHTML`  
3. **Location of Change**: Inside the for loop that iterates over wrapper.`querySelectorAll('a')`.

**Code Snippet to be Added:**
```ts
// Insert this block after the `if (!a.href.startsWith(prefix)) continue;` line.

const hrefContent = decodeURIComponent(a.href.substring(prefix.length).split('#')[0]);  
const innerText = a.innerText;

// Check if it's a citation link (starts with @) and is aliased (href content is different from the inner text).  
// This is the key logic: we are intercepting links where the destination and the display text are different.  
if (hrefContent.startsWith('@') && hrefContent !== innerText) {  
    // If it is an aliased citation, replace the entire <a> element with just its text content.  
    a.outerHTML = innerText;  
    // Skip the rest of the link processing for this element and move to the next one.  
    continue;  
}
```

This logic ensures that by the time the HTML is sent to Pandoc, the aliased citation has been "flattened" to plain text, while standard citations and other internal links are left intact for further processing.
